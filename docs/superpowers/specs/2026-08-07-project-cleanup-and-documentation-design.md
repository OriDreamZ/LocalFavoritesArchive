# 项目清理与文档完善设计

## 目标

将 Local Favorites Archive 整理为可继续开发和发布的空数据项目：清除项目内已经归档的 X 收藏及可再生缓存，保留现有功能和历史设计记录，并建立面向使用、开发和维护的长期文档体系。

## 已确认决策

- 采用标准化清理方案，不进行与本次目标无关的源码重构或目录重组。
- 保留 `docs/superpowers/plans/` 与 `docs/superpowers/specs/` 中已有的历史设计和实施计划。
- 新增长期维护文档，避免 README 承担所有技术细节。
- 许可证采用 GNU General Public License v3.0 or later，对应 SPDX 标识 `GPL-3.0-or-later`。
- 数据清理范围只限本项目内的归档目录和明确可再生的缓存，不处理 Chrome 用户资料、登录状态、扩展设置、虚拟环境或仓库外文件。

## 数据清理设计

### 删除范围

清除默认归档目录 `archive/` 中的全部运行数据，包括：

- SQLite 数据库及其中的推文、媒体、标签、同步状态和任务记录；
- `media/` 中已下载的图片、视频及其他媒体；
- `raw/` 中保存的原始响应或调试数据；
- 归档目录内由程序生成的其他临时文件。

同时删除 `.pytest_cache/`、源码目录和测试目录下的 `__pycache__/` 等明确可再生的开发缓存。`.venv/` 保留，避免重新安装运行环境。

### 安全边界

数据删除不可恢复，实施前必须：

1. 将归档目录解析为绝对路径，并确认其位于项目根目录内且精确指向 `archive/`。
2. 检查占用服务端口的进程，只停止可确认属于本项目的服务。
3. 不使用模糊通配符、未解析的环境变量或仓库根目录作为递归删除目标。
4. 不触碰 Chrome 配置、浏览器登录资料、扩展本地存储及任何仓库外目录。

### 空状态重建

删除旧归档后，通过项目现有初始化入口重新创建归档结构。初始化结果应包含可用的空数据库和程序要求的空目录，所有业务表记录数均为零。此步骤用于验证“初始化无数据状态”，而不是保留一个无法启动的缺失目录状态。

## 文件清理原则

- 保留源码、测试、Chrome 扩展、项目配置和全部已跟踪历史设计文档。
- 删除构建、测试或解释器能够自动重建的缓存。
- 对无法明确判定用途的文件不做删除。
- 不借本次清理改写现有业务逻辑、撤销已完成功能或进行大范围重构。
- 更新 `.gitignore` 时只补充实际需要忽略的运行产物，避免隐藏应提交的项目文件。

## 长期文档结构

新增以下中文文档：

- `docs/FEATURES.md`：功能范围、主要工作流、非目标和功能限制。
- `docs/ARCHITECTURE.md`：服务、浏览器扩展、数据采集、持久化和页面之间的关系。
- `docs/UI-DESIGN.md`：信息架构、页面职责、交互状态、响应式与可访问性约束。
- `docs/DEVELOPMENT.md`：开发环境、依赖安装、测试、代码组织和变更规范。
- `docs/DATA-STORAGE.md`：归档目录、数据库与媒体结构、去重、删除和备份规则。
- `docs/SECURITY-AND-LIMITATIONS.md`：账号与隐私边界、平台变化风险、合法使用要求和已知限制。

历史过程文档继续保存在 `docs/superpowers/`，但 README 和长期维护文档不依赖读者阅读这些过程记录。

- 项目定位、适用场景和非官方性质；
- 已实现功能与关键限制；
- 当前主要支持的 Windows、Google Chrome 和 Python 3.11+ 环境；
- 安装、初始化、启动和关闭步骤；
- Chrome 扩展加载、首次登录和同步流程；
- 连续已有内容停止阈值、媒体下载与同步进度说明；
- 本地浏览、排序、筛选、分页、标签和删除操作；
- 默认数据目录、备份与彻底清空方法；
- 常见故障排查、开发测试和项目目录结构；
- 数据隐私、平台兼容风险及合法使用声明；
- `GPL-3.0-or-later` 许可证说明和贡献入口。

README 以普通使用者可完成首次启动为首要目标，深层实现细节通过链接指向 `docs/`。

## 验收标准

- 项目服务已停止后再执行数据清理，删除目标已验证位于项目内。
- 旧推文、媒体、标签、原始响应和同步记录全部清除。
- 空归档重新初始化成功，推文数与媒体数均为零，页面可以正常打开并显示空状态。
- 可再生缓存已清理，虚拟环境和用户浏览器资料未受影响。
- README 无乱码，安装和使用步骤能从干净环境顺序执行。
- 六份长期文档内容彼此一致，功能名称、路径、端口和命令与代码保持一致。
- 根目录包含完整 GPL v3 许可证，项目元数据使用 `GPL-3.0-or-later`。
- Python 测试、扩展 JavaScript 语法检查和空状态页面验证通过。

## 非目标

- 不保证绕过 X 的登录、访问控制或反滥用机制。
- 不引入 X 官方收费 API。
- 不清理用户的 Chrome 个人资料或重置扩展设置。
- 不重构现有采集、去重、标签、分页或删除功能。
- 不删除 Git 历史中已经提交的开发过程文档。
