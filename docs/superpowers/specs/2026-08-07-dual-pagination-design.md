# Dual Pagination Design

## Goal

在“我的收藏”页面的内容列表前后各提供一套完整分页组件，使用户在连续浏览时无需滚动到列表另一端即可翻页或跳转。

## Interface

- 顶部分页位于收藏标题和每页数量选择器之后、第一条收藏内容之前。
- 底部分页保留在最后一条收藏内容之后。
- 两套组件均包含上一页按钮、当前页与总页数、总结果数、下一页按钮、页码输入框和跳转按钮。
- 顶部分页使用“顶部推文分页”无障碍名称，底部分页继续使用“推文分页”。

## Shared State

- `currentPage` 和 `totalPages` 仍是唯一分页状态来源。
- `updatePageControls(total)` 同时更新两套组件的页码文本、按钮禁用状态、输入框最大值和当前输入值。
- 任意一套组件触发上一页、下一页、跳转或回车跳转后，另一套组件立即同步。
- 筛选条件或每页数量变化后，两套组件同时回到第一页。

## Navigation Behavior

- 通过顶部组件换页后，将页面平滑滚动到收藏内容区域顶部，避免跳回整个应用顶部。
- 通过底部组件换页后也滚动到收藏内容区域顶部，使下一页从第一条内容开始阅读。
- 页码输入继续被限制在 `1` 到 `totalPages` 范围内。

## Responsive Layout

- 桌面端两套组件均保持居中横向排列。
- 窄屏继续使用现有三列分页布局，页码输入与跳转按钮换到第二行。
- 不增加横向滚动，不缩小现有按钮触控区域。

## Testing

- HTML 契约测试确认顶部和底部分页组件同时存在，且不存在重复 ID。
- JavaScript 契约测试确认分页控件通过共享集合绑定和同步，而不是只更新底部 ID。
- 浏览器验证从顶部翻到下一页，检查上下页码均变为第二页；再从底部跳转到指定页，检查顶部同步。
- 在桌面和移动端检查两套分页均无重叠或横向溢出。

## Out Of Scope

- 不改变后端分页 API、每页数量选项、筛选条件、排序规则或收藏卡片结构。
- 不新增数字页按钮列表或无限滚动。
