# 多标签筛选、续接同步与局域网访问设计

## 目标

在不使用官方收费 API 的前提下，增加多标签交集或并集筛选；让 Chrome 扩展默认从当前 Likes 页面已加载内容和当前滚动位置继续采集，不刷新页面；提供可选的局域网完整管理访问。

## 多标签筛选

收藏页面使用可多选的标签控件和“全部满足”“任一满足”模式。接口使用重复的 `tag_ids` 查询参数与 `tag_mode=all|any`；旧 `tag_id` 保持兼容。`all` 以每个标签一个 `EXISTS` 条件实现交集，`any` 使用一个 `EXISTS ... IN (...)` 条件实现并集。列表和计数必须共享同一过滤条件，空选择不施加标签过滤。筛选条件写入 URL 查询参数，刷新、分页和返回页面仍可还原。

## 从当前位置继续同步

扩展默认不刷新当前 Likes 页面。启动时先附加调试协议、采集当前已渲染推文 DOM、保留页面滚动位置，再由滚动驱动器继续向下请求和监听 Likes GraphQL 响应。弹窗额外提供“从头重新同步”，仅该模式刷新或导航至 Likes 页面。

DOM 采集和网络响应采集均转换为 `Post` 后提交，SQLite 的推文 ID 去重为最终保障。DOM 仅负责当前可见内容和可用媒体元数据；`blob:` 视频地址不作为可下载来源，后续网络响应仍优先补全真实媒体地址。连续已有推文停止条件、手动停止、媒体下载和失败重试沿用现有流程。

## 局域网访问

默认服务仍绑定 `127.0.0.1`。新增 `--lan`，启用时绑定 `0.0.0.0`，同步中心与命令行显示主机实际局域网 IPv4 访问地址。局域网模式无认证，所有设备拥有完整浏览、同步、标签、设置、删除和媒体重试权限。服务不自动修改 Windows 防火墙；文档提供手动放行和撤销说明，并明确禁止端口映射、公网暴露或反向代理。

局域网模式下 API 保持同源页面调用，扩展继续只使用 `127.0.0.1`。所有会修改归档的请求要求现有页面脚本发送自定义请求头，以降低跨站表单请求风险；此机制不是身份验证，也不会限制局域网用户。

## 验证

测试覆盖交集、并集、旧参数兼容、列表与计数一致性、筛选 URL 还原、当前 DOM 采集、默认不刷新、从头模式刷新、DOM/网络去重、局域网开关和默认回环绑定。浏览器验证使用隔离归档，在桌面和窄屏检查多标签控件与同步弹窗；局域网验证使用本机第二访问地址，不修改真实归档。
