# Chrome 扩展采集规范

扩展默认提供“从当前位置继续”和“从头重新同步”两种模式。前者不刷新当前 Likes 页面，先读取当前已渲染的推文，再从当前滚动位置向下滚动；后者刷新页面后重新捕获网络响应。

DOM 采集只接受带状态链接和时间的推文，记录正文、作者、发布时间、原始链接和可用媒体。`blob:` 视频地址不可作为本地下载来源，真实视频地址仍以之后捕获的网络响应为准。DOM 批次与 GraphQL 批次都通过推文 ID 去重。
## 当前采集规则

为避免 X 页面 DOM 中的视频缩略图或 `blob:` 地址被误判，扩展已移除 DOM 补采和不刷新续采流程。每次同步都必须刷新 Likes 页面，并只读取刷新后捕获的 Likes GraphQL 网络响应。请不要在同步过程中切换标签页或手动滚动到其他页面。

同步中心会显示失败媒体对应的推文 ID、作者昵称、@账号、原文链接、媒体序号和具体校验错误。视频地址缺失、缩略图地址、图片响应冒充视频响应、响应 MIME 与媒体类型不一致时，系统会拒绝入库并保留失败记录，用户可在同步中心逐条重试。
